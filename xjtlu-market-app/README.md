# U Use App

西浦双校区物品共享的可运行 MVP，用于小范围流程测试。当前采用共享试用身份和本地持久化数据，借还记录、收藏、发布审核和举报操作可实际运行。

## 运行

建议 Node.js 22 或 24。

```bash
npm ci
cp .env.example .env.local
# 修改 ADMIN_PASSWORD 为自己的密码。
npm run dev
```

学生端：http://localhost:3000。后台：http://localhost:3000/admin，用户名 `admin`，密码为 `ADMIN_PASSWORD`。开发模式允许学生端试用，后台仍需登录。

```bash
npm test
npm run build
npm run lint
npm run test:api
npm start
```

生产启动默认关闭共享试用接口。仅在本地展示构建版时设置 `DEMO_MODE=true`。共享试用身份不得用于收集真实个人资料。`npm run reset` 会覆盖物品、预约和举报数据，仅用于重置演示。

## 当前功能

- 双校区、搜索、分类、使用方式、价格排序，失败可重试。
- 收藏保存到当前浏览器，可取消或筛选。
- 发布表单根据使用方式显示价格字段，默认使用当前校区。
- 发布进入审核；后台通过或拒绝。
- 预约保存交付点、借出和归还时间、押金快照；校验可用日期、交付校区、重复时段。
- 后台按预约状态推进借还，可取消早期预约。
- 买断确认交付后完成交易，无需归还；已卖出的物品从可用列表下架。
- 借还页展示实际记录，支持刷新与交付点导航。
- 举报关联具体物品，后台处理。
- 手机与桌面布局、键盘焦点、Escape 关闭弹窗；失败时保留表单。

## 架构与上线条件

`components/`：发现、地图、发布、借还和后台。
`app/api/`：输入校验和 HTTP 状态。
`lib/data.ts`：持久化和预约冲突。
`lib/booking-state.ts`：共享状态流转。
`middleware.ts`：后台登录、跨站写入限制、试用模式边界。

JSON 先保存临时文件再原子替换，写队列失败后可以恢复；物品和预约写操作在单进程内串行。可通过 `DATA_DIRECTORY` 指定持久化目录。

当前存储适合单进程本地测试，不适合无持久磁盘的 Serverless、多实例或真实收费服务。正式试点仍需真实学生账号、按用户隔离数据的数据库、图片存储和通知服务；`supabase/schema.sql` 是未接入的结构草稿。当前没有真实邮箱验证、聊天或支付，押金字段仅记录金额。

种子物品、预约、举报均为示例。日期平移只在开发模式或明确启用的演示模式生效，示例数据不构成真实用户验证证据。

## 验证

`npm test` 在临时目录验证并发预约、取消释放时段、非法状态跳转、物品存在性、交付校区、日期顺序和失败后写队列恢复，不修改演示数据。发布前还需检查两校区地图、屏幕尺寸和真实基础设施配置。
