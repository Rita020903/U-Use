# 汤鋆秋的职责与交接

## 你对什么负责

把需求与测试问题转成优先级、验收标准和版本计划，组织三方案比较、pivot/persevere讨论，协调改动与复测并记录取舍。

边界：不默认负责编程；不把新功能数量当迭代效果；不按已有产品必胜的目标倒调评分。

每阶段主产出名建议为“阶段_迭代记录_v1.md”，存入“交付物”。原始研究、敏感贡献和私人回执按课程隐私约定存私有库；目录内只放去标识摘要和索引。无需为了填满目录编造结果。

## 收到什么与交给谁

收到需求、真实测试、版本和分析；交Rita有边界的改动清单，交李元龙复测任务；给汪睿有证据的迭代故事。

主要交接对象：Rita、李元龙、汪睿、黄禹轩。角色互审人：李元龙；这是内部工作安排，正式评分由课程方决定。

## 完成标准

- [ ] 有实际产出、日期、版本与可追溯来源，不只是口头说完成。
- [ ] 原始值、推断、假设、技术检查和合成例子分开；反面证据未隐藏。
- [ ] 李元龙或对应领域独立复核者看过，并记录具体意见。
- [ ] 交接对象拿到可读版本，黄禹轩的日志包含实际状态及未解决问题。
- [ ] 本人真实贡献、协作、反馈和AI参与已记录，为A4留证据。

互审不等于代写；不得把队友或AI独立完成的工作称为本人完成。
